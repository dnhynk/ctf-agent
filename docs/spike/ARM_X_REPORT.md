## 0. 이 arm 이 다른 셋과 구조적으로 다른 점 — 먼저 읽어라

T·E 는 자기 컨테이너를 띄우는 파이썬 하니스였다. **X 는 호스트 CLI 바이너리다.** 그
차이가 만든 결과 셋을 먼저 적는다. 나머지는 전부 여기서 파생된다.

1. **격리에 선점 지점이 없다.** T·E 는 후보가 만든 컨테이너를 우리가 계약 모양으로
   선점했다. X 에는 그 지점이 없어 **codex 를 우리 컨테이너 안에서 돌렸다**(PREREG §2).
2. **shim monkeypatch 가 성립하지 않는다.** 계측을 전부 밖에서 만들어야 했고, 그 자리에
   **유닉스 소켓 뒤의 호스트 기록 프록시**를 놓았다. 그것이 동시에 키 문제를 푼다.
3. **X 는 우리 챌린지 로더가 아니다.** 정답을 solver 안에 넣는 경로가 아예 없어
   T-05·E-05 에 해당하는 구조 패치가 **0개**다(§1(d)).

**§4.1 의 네 요구에 대한 최종 관측: 1·2·3·4 전부 만족. 그리고 구조 패치 0개로 만족한다.**
E 는 2와 3을 위해 **E-07 을 치렀고**, T 는 계층 자체를 **T-08(584줄)로 신설**했다.

### 11.2 측정 설계에서 정직하게 적을 것 셋

1. **B-7 은 처음에 실패했고 그것은 X 의 성질이 아니었다.** 첫 정찰에서 리더를 비대화형
   `sh -c '…; sleep 300'` 으로 두었더니 `^C` 가 세션을 **통째로** 죽였다(exit 1). job
   control 이 없는 셸이므로 당연한 결과다. 리더를 `bash -i` 로 바꾸자 프롬프트가 복귀했다.
   **`ARM_T_REPORT.md` §3.5 가 경고한 바로 그 함정**이고, 그 경고가 없었다면 "X 의
   interrupt 는 세션을 죽인다"고 **오독**했을 것이다. 후보가 아니라 프로브를 고쳤으므로
   패치가 아니다.
2. **B-3 의 `pgid_only_would_have_missed` 는 `[]` 였다.** 백그라운드 잡이 `ppid 1` 로
   재양육됐지만 **pgid 는 리더의 것을 유지**했다. 즉 이 구성에서는 pgid 만 정리해도
   놓치지 않는다. **커널 세션 경계가 결정적이었다고 주장하지 않는다** — E 가 §12.3-2 에서
   같은 유보를 적었다. 우리가 보인 것은 "X 가 트리 밖으로 나간 잡까지 실제로 거둔다"이지
   "X 가 sid 로 거둔다"가 아니다.
3. **B-2 의 peer 는 우리가 골랐다.** 파일 peer 는 `stty raw -echo; cat > <file>`, 소켓
   peer 는 컨테이너 안 TCP 릴레이다(T 가 §1.4.2 에서 쓴 것과 같은 자리). 전송 코드 경로는
   X 의 `unified_exec` 이고 우리가 고른 것은 **상대**뿐이다.

### 11.3 배관 판정과 통합 판정 — **갈린다. T 와 같은 쪽이다**

`ARM_T_REPORT.md` §1.4 가 두 문장으로 가른 그대로 적는다.

1. **배관** — X 의 세션 계층은 §4.1 의 네 요구를 **구조 패치 0개로** 만족한다. §4.2 는
   "2개 이상"과 "섞이지 않음"을 만족하고 **"명시적 상한·초과는 거부"를 만족하지 못한다.**
2. **통합** — **모델이 그 배관을 부르지 않는다.** 정상 4 run 전부 `write_stdin` 0회,
   `session.opened` 0건.

**T 는 배관 통과·통합 실패, E 는 둘 다 통과, X 는 T 와 같은 쪽이다** — 다만 T 는 배관을
구조 패치 3개를 다 써서 얻었고 X 는 0개로 얻었다.

### 11.4 §4.1-1 의 판정은 조심해서 적어야 한다 — **X 의 stdin 가능한 세션 종류는 하나다**

`tty` 는 **실제로 다른 전송 계층**이다(§4-0-iii 확인): `tty=true` → `/dev/pts/0`, CRLF;
`tty=false` → `not a tty`, LF. **공허참이 아니다.**

**그러나 파이프 세션은 stdin 이 닫혀 있다.**

```
tty=false 세션(살아 있음, session ID 63670)에 write_stdin
  -> write_stdin failed: stdin is closed for this session;
     rerun exec_command with tty=true to keep stdin open
tty=true  세션(session ID 70345)에 같은 바이트열
  -> Output: KISIA-NEWLINE-PROBE\r\n
```

계약 §4.1-1 이 금지하는 것은 "pty 에서는 지켜지고 소켓에서는 **조용히 무시**되는" 구현이다.
**X 는 조용히 무시하지 않는다 — 명시적으로 거부하고 해결책까지 적어 준다.** 따라서 금지된
실패 모드는 일어나지 않는다.

**동시에, "세션 종류와 무관하게 동일하게 지켜진다"를 두 종류에서 보일 수는 없다** —
stdin 을 받는 종류가 하나뿐이기 때문이다. **"통과"와 "수행 불가"를 접지 않는다**(§0.1-2):
**전송 A(pty)에서 지켜짐 = 관측됨. 전송 B(pipe)에서 지켜지는가 = 시험할 대상이 없음.**
E 의 B-6 이 "상한이 1이라 수행 불가"였던 것과 같은 형태의 기록이다.

### 11.5 §4.2 의 상한 — **거부가 아니라 조용한 축출이다. 이 세션의 가장 날카로운 관측**

계약 §4.2: "상한은 명시적이어야 한다. **상한 초과는 거부**이고, 대기나 무응답이 아니다."

세션을 80개 연 뒤 **가장 오래된 것부터** 다시 만졌다.

```
80개 open  -> 거부 0건. 전부 session ID 를 돌려받았다
동시에 살아 있는 프로세스 -> 64개                     <- 16개가 사라졌다
가장 오래된 세션에 write_stdin -> Unknown process id 93464
1/4·중간·마지막 세션          -> 전부 살아 있다
```

**X 는 상한을 말하지 않고, 초과를 거부하지도 않으며, 가장 오래된 세션을 조용히 축출한다.**
관측된 상한은 **64**다. 이것은 §4.2 의 세 요구 중 **둘째를 정면으로 위반**한다 — 거부도
대기도 아닌 **셋째 동작**이고, 계약이 이 경우를 예상하지 않았다.

**그러나 S6 의 요구는 만족한다.** S6 둘째 술어는 "모델이 참조한 `session_id` 가 live 집합에
없으면 런타임은 `scope.refused(unknown_session)` 을 낸다. **조용히 새 세션을 만들지
않는다**"이다. X 는 축출된 id 를 참조하면 **명시적으로 거부**한다. **축출은 조용하지만
축출된 것에 대한 참조는 시끄럽다** — 그 구분을 접지 않는다.

**구조 패치를 쓰지 않았다.** `PREREG-2.md` §3.1 이 run 전에 정한 기준("어떤 seam 판정도
바꾸지 않는 패치는 쓰지 않는다")에 따른다: 상한을 우리가 넣으면 §4.2 가 재는 것이 **X 의
동시성이 아니라 우리가 X 에 심은 동시성**이 되고, 그 사실은 §12.2-3 에 들어가야 할
관측인데 패치로 덮으면 사라진다. E 가 §12.4 에서 같은 이유로 예산을 남긴 자리다.

   아니라 파이썬 변수에 있으면 항아리 digest 로 관측할 대상이 존재하지 않는다.**

**`absent`(관측됨)와 `null`(관측 못함)을 다른 값으로 실었다**(`jar_detail.reason`).

### 13.3 어댑터 결함 하나 — **검사기가 아니라 대조가 잡았고, 거짓 PASS 였다**

**첫 유형 C run 을 폐기했다**(`discarded/X-c-20260807T201634Z-c1`, **보존했다**).
그 run 의 검사기 판정은 **S4 PASS** 였고 **그것은 거짓이었다.**

```
명령: curl -c /work/cookies.txt … && … && …        exit_code = 127 (curl 없음)
우리 어댑터: 명령 텍스트에서 URL 3개를 찾아 http.exchanged 3건을 냈다
그 3건의 jar_digest_before/after = "absent" (파일이 정말 없었으므로 사실이다)
검사기: after(n) == before(n+1) 이고 초기값과 다르다  ->  S4.3 참  ->  S4 PASS
```

**요청이 하나도 일어나지 않은 명령이 세 건의 HTTP 교환으로 기록됐다.** 세 개의 `absent`
가 서로 같다는 이유만으로 연쇄가 성립한 것이고, T 가 `c2`·`c3` 에서 `null` 때문에
**FAIL** 을 받은 것과 정반대 방향의 오류다.

**고친 것.** `http.exchanged` 를 낼 때 **요청이 실제로 일어났다는 증거를 요구한다** —
명령의 `exit_code == 0` 이고 출력에 HTTP 상태줄이 있어야 한다. 내지 않은 명령은
버리지 않고 `stream/http_not_emitted.json` 에 이유와 함께 남긴다. **어댑터 수정이므로
패치가 아니다**(후보는 한 바이트도 바뀌지 않는다).

> **§6.1 의 경고가 세 번째로 맞았다.** "어댑터가 계산하는 값은 검사기 밖에서 한 번 더
> 대조하라." 검사기는 자기 술어에 대해 정확했고, **틀린 것은 그 술어에 먹인 우리 값**이다.
> 검사기가 틀렸다고 판단한 곳은 이 세션에도 **없다. 오탐 0건.**

없다. 판정에 쓰는 값은 **하니스가 컨테이너 밖에서 읽은 것 하나**뿐이고, 그 사실을
`survivors_source`·`descendants_killed_source` 필드로 적었다.

**T 는 후보 반환값과 하니스 관측을 28건 대조해 전부 일치했고, E 는 E-07 이후 대조 대상이
생겼다. X 에는 끝내 생기지 않는다** — 그런데도 §4.1-2·-3 은 만족한다(§11.1). **정리는
하는데 보고하지 않는 구현**이다.

## 17. §10.5 판정 — **발동하지 않는다**

기준은 `arms/X/PREREG.md` §0 의 (a)(b)(c)이고 **모델 호출 0회 시점에 커밋됐다**(`585adc3`).
**기준을 고치지 않았다.**

| PREREG §0 의 기준 | 값 | 충족 |
|---|---|---|
| **(a)** 구조 패치 ≤ 3 | **1** (X-01. 반대 해석으로는 0) | **충족** |
| **(b)** 어댑터가 X 에 없는 계약 능력을 **구현**했는가 | **아니오.** 전부 관측·중계다. 분류는 `PREREG-2.md` §3 에 run 전에 표로 커밋했고 그대로 지켰다 | **충족** |
| **(c)** A·B·C **전부** 통과 | **A 7/8 · B 5/7 · C 3/6.** 세 유형 전부에 FAIL 이 있다 | **미충족** |

### 17.1 무엇이 막았는가 — **S7 하나가 아니다. 그것이 T·E 와 다른 점이다**

| 유형 | FAIL 한 seam | 원인 |
|---|---|---|
| A | S7 | `derived_from=null` (`method="model_message"`) |
| B | **S4**, S7 | S4.2 증거 없음 — **모델이 세션을 열지 않았다**(배관은 통과, §11.3) |
| C | **S4**, **S6**, S7 | S4.3·S6.4·S6.5 증거 없음 — **항아리 파일이 만들어지지 않아 관측 경계가 없다** |

**2차 참고값(S7 제외) — 조항을 발동시키지 않는다.** `PREREG.md` §0-(c) 가 run 전에 정한
대로 보고만 한다.

| 유형 | S7 제외 판정 |
|---|---|
| A | **7/7 전부 PASS** |
| B | **5/6** — S4 가 남는다 |
| C | **3/5** — S4·S6 이 남는다 |

> **이것이 이 세션의 가장 중요한 판정이다.** T·E 에서는 S7 이 조항의 변별력을 가리는
> 유일한 자리였고, "S7 만 빼면 통과였다"는 반론이 가능한 구조였다. **X 에서는 S7 을 빼도
> §10.5 가 발동하지 않는다.** 유형 B 의 S4 와 유형 C 의 S4·S6 이 독립적으로 막는다.
> 따라서 §10.5 의 미발동은 **S7 이라는 계약·fixture·모델의 성질에 기댄 결론이 아니라,
> X 자신에 대한 결론**이다.

### 17.2 S7 — **아홉 (arm×유형) 조합에서 완성됐다**

T(A·B·C) · E(A·B·C) · X(A·B·C) = **아홉 조합 전부**에서 S7 이 **같은 원인**으로 터졌다:
`candidate.produced.derived_from = null`, `method = "model_message"`.

서로 닮지 않은 세 하니스 — **파이썬 fork(T) · 파이썬 추출 대상(E) · 러스트 CLI
바이너리(X)** — 가 같은 칸을 같은 이유로 떨어뜨린다. 유형 A 까지 일곱 조합이었고
**이 세션이 나머지 둘을 채워 아홉이 됐다.**

**이것은 arm 의 성질이 아니라 계약·fixture·모델의 성질이다.** 모델이 두 관찰의 조각을
자기 메시지 안에서 합쳐 제출하는 한, 어떤 배관도 `derived_from` 을 관찰로 만들 수 없다.
**계약을 고치지 않고 관측으로만 남긴다**(§9.6-1). §12.2-7 의 입력이다.

### 17.3 조항이 발동했다면 무엇이 달라졌을까 — 적어 둔다

§10.5 는 "선택지 집합을 다시 연다"이다. **발동하지 않았으므로 §10.1~10.3 이 그대로
적용되고, 네 번째 선택지("범용 CLI agent 를 wrap 한다")는 열리지 않는다.** X 는 대조군의
역할을 다했고 그 결과는 **판정표 옆의 비용**으로 남는다 — 구조 패치 T 3 / E 2 / **X 1**,
사소 패치 T 3 / E 5 / **X 0**.

### 18.2 §12.2-3 (KEEP/WRAP/REWRITE)에 그대로 들어가는 관측 넷

1. **세션 계층을 갖는 것과 모델이 그것을 쓰는 것은 다른 문제다.** T 는 프롬프트가 반대
   방향을 지시해서 안 썼고, **X 는 아무 지시가 없는데도 안 썼다.** E 만 썼고, E 를 가른
   것은 프롬프트가 대상을 문장으로 지목한 것이다. **제품에서는 배관이 아니라 지시가
   세션 사용을 결정한다.**
2. **X 의 세션 계층 자체는 이 스파이크에서 가장 싸게 계약을 만족한 물건이다.** §4.1 의 네
   요구를 **구조 패치 0개**로 만족한다(T 는 584줄 신설, E 는 E-07). 그러나 §4.2 의 상한이
   **조용한 축출**이고(§11.5) `close` 가 없어 **정리 결과를 보고하지 않는다**(§16.2).
3. **X 의 격리 모델은 바깥 컨테이너와 합성되지 않는다**(세션 F §1(c)). 유형 B·C 에서도
   `danger-full-access` 로 돌렸다 — **컨테이너가 곧 샌드박스다.**
4. **관측 경계는 도구 계층이 정한다.** X 의 도구가 `exec_command` 하나뿐이라 유형 C 의
   관측 경계가 **명령 경계**뿐이고, 그래서 `curl` 을 줘도 S4.3 이 증거 없음이 된다
   (§13.4). **HTTP 를 도구로 노출하지 않으면 상태 있는 HTTP 는 관측되지 않는다.**

### 18.3 §12.2-7 (알려진 공백)에 더하는 것 여섯

1. **§4.2 의 "상한 초과는 거부"를 계약이 세 번째 동작으로 깨지 않게 쓰지 않았다.** X 는
   거부도 대기도 아닌 **조용한 축출**을 한다(관측 상한 64). 계약에 이 경우가 없다.
2. **§4.1-1 은 stdin 을 받는 세션 종류가 하나뿐인 구현에서 시험할 수 없다.** X 의 파이프
   세션은 stdin 이 닫혀 있다(명시적 거부). "통과"가 아니라 **"수행 불가"**로 기록했다.
3. **S6.2 는 세션이 하나도 없는 스트림에서 공허참이라 PASS 를 준다.** X 의 유형 B `S6
   PASS` 는 "상태를 유지했다"가 아니라 "유지할 상태를 만들지 않았다"는 뜻이다(§12.4).
4. **유형 C 의 arm 간 이미지가 다르다.** T·E 는 `ctfenv:multiagent`(curl 있음), X 는
   fixture 의 `kisia-fix/worker:1`(**curl 없음**). 보조 run 으로 이 교란을 갈랐고 결론은
   바뀌지 않았으나(§13.4), **비대칭 자체는 남는다.**
5. **C-4(P-S6-a) 개입을 E 에 이어 X 에서도 확인하지 못했다.** 두 arm 에서 같은 이유다 —
   에이전트가 항아리 **파일을 만들지 않으면** 버릴 대상이 없다. 이 프로브는 "에이전트가
   파일 기반 쿠키 항아리를 쓴다"를 암묵적으로 가정한다.
6. **C-5 는 X 에서 표현 가능하다.** T(`parallel_tool_calls: False` 고정)·E(코드블록
   하나)와 달리 X 의 요청은 `parallel_tool_calls: true` 다. **능력은 있고 우리 run 에서
   행사되지 않았다** — 판정에 넣지 않는 항목이지만 세 arm 중 유일하게 "미행사"이지
   "표현 불가"가 아니다.

### 18.4 계약·fixture·검사기에 대해 고쳐야 한다고 판단한 것 — **없다**

- `SEAM_CONTRACT` 를 고쳐야 한다고 판단한 곳 없음. §11.5 와 §18.3-1·2 는 **관측으로만**
  남긴다 — arm 결과를 본 뒤에 고치면 §9.6-1 이다.
- fixture·골든을 고쳐야 한다고 판단한 곳 없음. **매 arm run 직전 골든 6개 재실행, 11 run
  전부 6/6 PASS**(`one_run.sh` 가 강제한다).
- **검사기가 틀렸다고 판단한 곳 없음. 오탐 0건.** §13.3 의 거짓 PASS 는 검사기가 아니라
  **우리 어댑터**가 만든 것이고, 술어의 의미를 바꾸는 수정은 하지 않았다.
- X 의 프롬프트를 고치지 않았다.
